# Write or update documentation

Goal: documentation that matches the code as it is today.

1. Find what exists: the README, a docs folder, a contributing guide, and the comments in the code under discussion. Read the code they describe.
2. Check every claim against the code: commands, options, defaults, file names, environment variables and examples. Run the commands you document whenever you can.
3. Change only what the request covers: correct what is wrong or outdated, add what is missing, remove what no longer exists. Keep the project's tone, structure, language and formatting.
4. In code comments, explain why rather than what. Document public functions in the style the file already uses, and delete comments that no longer match the code.
5. Keep it short and concrete: a working example is worth more than a paragraph.
6. Finish with a list of what you changed and anything you could not verify.

Do not invent features, flags or behaviour the code does not have.
